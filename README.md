## 🔬 Ноутбуки для сравнения моделей

Созданы компактные версии для сравнения разных архитектур детекторов объектов:

### 1. `Faster_RCNN_comparison.ipynb`
**Faster R-CNN** - двухэтапный детектор с высокой точностью:
- ✅ Region Proposal Network (RPN) для генерации предложений регионов
- ✅ ResNet50-FPN backbone для мультимасштабного обнаружения
- ✅ Высокая точность обнаружения
- ⚠️ Медленнее одноэтапных детекторов
- 🎯 **Лучший выбор для:** максимальной точности обнаружения

### 2. `YOLO_comparison.ipynb`
**YOLOv8** - одноэтапный детектор для real-time приложений:
- ✅ Anchor-free подход (без якорных боксов)
- ✅ Очень быстрая скорость inference
- ✅ Простота использования через ultralytics API
- ✅ Отличный баланс скорости и точности
- ⚠️ Может быть менее точным на мелких объектах
- 🎯 **Лучший выбор для:** real-time обнаружения, видеопотоков

### 3. `SSD_comparison.ipynb`
**SSD (Single Shot MultiBox Detector)** - баланс между скоростью и точностью:
- ✅ Мультимасштабные предсказания на 6 уровнях
- ✅ Использует anchor boxes разных размеров
- ✅ Хорошо работает с объектами разных размеров
- ✅ Встроен в torchvision
- ⚠️ Медленнее YOLO, но быстрее Faster R-CNN
- 🎯 **Лучший выбор для:** баланса между скоростью и точностью

## 📊 Метрики качества

Модель оценивается по следующим метрикам:

### Loss (Функция потерь)
- **Train Loss** - потеря на обучающей выборке
- **Validation Loss** - потеря на валидационной выборке

### Classification Metrics

- **Precision (Точность)** - доля правильно обнаруженных объектов среди всех обнаруженных
  ```
  Precision = TP / (TP + FP)
  ```

- **Recall (Полнота)** - доля обнаруженных объектов среди всех реальных объектов
  ```
  Recall = TP / (TP + FN)
  ```

- **F1-Score** - гармоническое среднее Precision и Recall
  ```
  F1 = 2 * (Precision * Recall) / (Precision + Recall)
  ```

Где:
- **TP (True Positive)** - правильно обнаруженные объекты (IoU ≥ 0.5)
- **FP (False Positive)** - ложные обнаружения
- **FN (False Negative)** - пропущенные объекты

### IoU (Intersection over Union)

Метрика для оценки качества локализации объектов:
```
IoU = Площадь пересечения / Площадь объединения
```

Объект считается правильно обнаруженным, если IoU ≥ 0.5.

## ❓ Часто задаваемые вопросы

### 1. Как увеличить точность модели?

- **Увеличьте количество эпох** (NUM_EPOCHS = 50-100)
- **Увеличьте размер датасета**
- **Добавьте аугментацию данных**
- **Настройте гиперпараметры** (learning rate, batch size)

### 2. Ошибка "Out of Memory" (OOM)

Если не хватает памяти GPU:
- Уменьшите BATCH_SIZE (до 2 или 1)
- Используйте меньшее разрешение изображений
- Запросите GPU с большей памятью (A100, V100)

### 3. Как изменить количество классов?

1. Подсчитайте количество уникальных классов в ваших аннотациях
2. Установите `NUM_CLASSES = количество_классов + 1` (добавляем фон)
3. Переобучите модель с самого начала

### 4. Модель не обнаруживает маленькие объекты

- Убедитесь, что аннотации корректны
- Увеличьте разрешение изображений
- Используйте модель с FPN (Feature Pyramid Network) - уже включена в Faster R-CNN
- Настройте anchor sizes в модели

```python
# Загрузка модели
```

```python
import albumentations as A

transform = A.Compose([
```

### Настройка anchor sizes

Для лучшего обнаружения объектов разных размеров:

```python
from torchvision.models.detection.anchor_utils import AnchorGenerator

# Создание генератора якорей
anchor_generator = AnchorGenerator(
    sizes=((32, 64, 128, 256, 512),),
    aspect_ratios=((0.5, 1.0, 2.0),)
)

# Передайте его при создании модели
model = fasterrcnn_resnet50_fpn(
    pretrained=True,
    rpn_anchor_generator=anchor_generator
)
```
